# Relative reference origins

A file/text expression is authored by the file that supplied its value. Raw object input uses the configured root directory. Dynamic selectors resolve before choosing a path. For ordinary relative paths, an existing target beside the author wins; otherwise retain the root-directory and existing find-up search. Absolute and home paths select their explicit target. TypeScript/JavaScript aliases resolve through the root's existing tsconfig/jsconfig mappings. An explicit filePathOverrides match against the requested path wins over all of these selections and its relative target uses the root directory.

Keep the requested spelling and selected lexical path for diagnostics. Use realpath for cache, dependency-cycle and security identity. Safety checks run on the final selected target after aliases, overrides and origin preference, including symlink boundaries. Internal provenance records use structural path identity and carry authored file, root, requested path, selected lexical target, canonical target and selection reason. The resolver registers the origin of expanded containers and follows it through nested references and self aliases; syntax substitution does not rewrite the caller's literals.

Legacy root/find-up fallback remains available when no authored sibling exists. This preserves existing shared-file layouts while resolving static and dynamic sibling paths consistently. Executable config exports follow the same origin rules as parsed JSON/YAML/TOML values. text() remains opaque; deployment raw file() inlining keeps its established known-reference substitution and foreign-reference passthrough.
