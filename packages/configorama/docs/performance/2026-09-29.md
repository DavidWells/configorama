# Optimization after startup round 2

Baseline: `59b410a` on `perf/startup-round2`, macOS arm64, Bun 1.2.18.
The baseline is also available in a detached worktree at
`/tmp/configorama-extreme-20260929/baseline`. Measurements include process startup.
No merge, release, or dependency upgrade is part of this work.

## Baseline and profiles

`hyperfine --warmup 3 --runs 30` measured plain import at 49.3ms under Bun
(p50 49.29ms, p95 52.49ms, p99 54.22ms; roughly 20 imports/s).
A separate `/usr/bin/time -l` run recorded 43,991,040 bytes maximum RSS.
Node CPU profiles and exclusive CommonJS module-load timings were captured before
changes; later profiles use fresh processes or repeated resolution of global.yaml.

The existing nine-scenario harness ran for 40 iterations before changes. Its CPU
profile (100 iterations per scenario) identified YAML preprocessing, match
rendering, and typo edit distance as the three largest application CPU hotspots.
One scenario, filters-mode, throws without CONFIGORAMA_STRICT_THREADS set; do not
interpret that timing as successful resolution. Subsequent comparisons set it to 2.

| Opportunity | Evidence | Impact | Confidence | Effort | Score |
| --- | --- | ---: | ---: | ---: | ---: |
| Load UI helpers on demand | Bun: chalk import chain 5.7ms, deep-log 1.9ms; main.js itself 9.4ms | 4 | 5 | 1 | 20 |
| Avoid exceptions in alias discovery | Global profile: find-up accessSync/access approximately 134ms across 300 loads | 3 | 5 | 2 | 7.5 |
| Native scan for YAML flow openers | YAML preProcess largest application hotspot in scenario profile | 3 | 5 | 1 | 15 |
| Bound typo comparisons by length | editDistance fifth overall profile entry, about 50ms | 2 | 5 | 1 | 10 |

## Change: load UI helpers only when displaying or debugging

Removed main.js's unused chalk import and moved deep-log imports to their existing
verbose, info, and debug call sites. The normal YAML require graph now asserts
that chalk, safe-chalk, supports-color, and deep-log are absent.

- Ordering preserved: yes; each logger is called in its original branch and order.
- Tie-breaking unchanged: N/A; resolution and error selection are untouched.
- Floating-point: identical; no arithmetic changed.
- RNG seeds: unchanged; no random state is used or modified.
- Golden outputs: `shasum -a 256 -c golden_checksums.txt` passed for all 224 fixture
  outcomes (180 successful resolutions, 44 expected errors), captured with fixed
  options and Date.now. Only the ESM fixture's clock is fixed, to avoid comparing
  different wall-clock timestamps. Global YAML output SHA-256 also matches.
- Validation: configorama full suite (2,468 passed), typecheck, require graph,
  and stdout hygiene passed.
- Rollback: revert the commit containing this section and its source change.

Side-by-side Bun measurements, 30 runs per command:

| Workload | Baseline | After UI change | Improvement |
| --- | ---: | ---: | ---: |
| Import | 49.6ms | 42.7ms | 13.9% |
| Import and resolve project-manager global.yaml | 63.0ms | 57.1ms | 9.4% |

Measurements and private-config hashes are retained under
`/tmp/configorama-extreme-20260929/`. The private config's contents and resolved
values are never printed or saved by its benchmark, only its output hash.

## Change: use nonthrowing existence checks for alias discovery

Replaced find-up 3's `accessSync`/catch loop for tsconfig/jsconfig discovery with
`existsSync`. Missing files are expected during an ancestor search; their exception
construction and unwinding dominated the repeated-global-config Node profile.
The lookup still observes the filesystem on every call; there is no cross-project
or cross-resolution cache. The dependency's ignored stopAt option remains ignored
in effect: search still reaches the root, preserving existing behavior.

- Ordering preserved: yes; search all ancestors for tsconfig first, then all for
  jsconfig, each nearest-first and including the root.
- Tie-breaking unchanged: yes; the same first existing candidate wins. Both F_OK
  access checks and existsSync follow symlinks and return false for inaccessible
  or missing paths. Existing directories still win and fail during read as before.
- Floating-point: N/A.
- RNG seeds: unchanged; only test temp-directory names use randomness.
- Golden outputs: all 224 fixture outcomes and the global YAML hash match. The
  16 real-filesystem alias tests also pass against the previous implementation.
  They cover precedence, deep ancestry, symlinks, config edits and repeated warnings.
- Validation: typecheck, full configorama suite (2,476 passed), and a fresh random
  fuzz run (10 properties, 2,000 cases each) passed.
- Rollback: revert the commit containing this section and its source change.

An isolated 30-run comparison measured Bun cold global loads at 59.2ms before
this change and 57.1ms after it (3.5%). Node's 550-load workload (50 warmups and
500 measured loads) fell from 730.0ms to 503.7ms across 30 fresh processes (31.0%).
Earlier measurements overlapped tests/fuzz and were discarded as contaminated.
Reprofiling shows the former approximately 134ms access/exception hotspot replaced
by approximately 20ms in existsSync across 300 global config loads.

The fixture oracle is retained as `scripts/perf-fixtures.js`. From the package:

```sh
node scripts/perf-fixtures.js /absolute/baseline/src /tmp/fixtures.json
shasum -a 256 /tmp/fixtures.json > /tmp/golden_checksums.txt
# Make one change, leaving the same git state/environment for both versions.
node scripts/perf-fixtures.js ./src /tmp/fixtures.json
shasum -a 256 -c /tmp/golden_checksums.txt
```
